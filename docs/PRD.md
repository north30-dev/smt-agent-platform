# 产品需求文档（PRD）
## 工业智能体平台 —— SMT产线智能运维与调度系统

**版本**：V1.0 | **日期**：2026年6月 | **技术栈**：Java (Spring Boot) + Python (LangChain/LangGraph)


## 一、项目概述

### 1.1 背景与定位

当前制造业正从“设备互联”演进为“智能决策”。工业AI智能体市场预计2030年达906亿元，年复合增长率43.6%。然而，**“有系统、缺智能；有人力、缺认知”** 仍是行业核心瓶颈——传统数字化解决了流程自动化，但大量高价值决策仍靠人。

本系统定位为面向**SMT贴片生产线**的工业智能体平台，通过多智能体协同，实现**“感知—决策—规划—执行”** 的全链路运营闭环。

### 1.2 目标用户

| 角色 | 职责 | 使用场景 |
|------|------|----------|
| 厂长/生产经理 | 全局监控与决策 | 查看产线总览、接收异常预警、审批调度方案 |
| 设备工程师 | 设备运维 | 查看设备健康度、接收维修建议、执行维保 |
| 工艺工程师 | 质量管控 | 分析不良品根因、优化工艺参数 |
| 生产班组长 | 现场执行 | 接收排产指令、报工、处理异常 |
| 操作工 | 一线操作 | 查看工单、上报问题、接收操作指引 |

### 1.3 核心价值

- **设备可用率提升**：预测性维护减少非计划停机
- **质量缺陷率下降**：AI根因分析定位质量隐患
- **排产效率提升**：智能调度应对急单插单
- **知识传承**：将老师傅经验沉淀为可复制的系统能力


## 二、生产线场景假设

### 2.1 产线概况

**某电子制造企业SMT贴片车间**，生产PCBA（印刷电路板组件），服务于消费电子客户。

| 属性 | 详情 |
|------|------|
| 产线数量 | 6条SMT贴片线 |
| 设备数量 | 约120台（印刷机、贴片机、回流焊、AOI检测仪等） |
| 日产能 | 约10万片PCBA |
| 产品种类 | 8种主流型号 + 频繁的NPI（新产品导入） |
| 人员规模 | 车间约80人（含管理、工程、操作） |

### 2.2 业务流程（中等偏复杂）

```
订单下达 → 物料齐套检查 → 生产排程 → 钢网/程序准备 → 
上料/换线 → SMT贴片 → 回流焊接 → AOI检测 → 
维修/返工 → 组装测试 → 包装入库
```

**典型痛点**：
1. **急单插单频繁**：排产依赖人工经验，响应慢
2. **设备突发故障**：平均每月2-3次非计划停机，每次损失2-4小时产能
3. **质量异常追溯难**：不良品需人工排查（物料、设备、工艺、人员）
4. **知识经验流失**：资深工程师稀缺，新人培养周期长
5. **多系统数据孤岛**：MES、EAM、QMS各自为政

### 2.3 多智能体协同架构

参考行业实践，本系统采用**多智能体协同（MAS）架构**，由**5大核心智能体**构成协同决策网络：

| 智能体 | 职责 | 类比 |
|--------|------|------|
| **调度智能体** | 全局排产优化、急单响应、资源调配 | AI生产调度员 |
| **设备运维智能体** | 健康监测、故障预测、维修建议 | AI设备管家 |
| **质量分析智能体** | 不良根因分析、工艺参数优化 | AI质检专家 |
| **知识助手智能体** | 文档检索、操作指引、经验问答 | AI老师傅 |
| **执行协同智能体** | 指令下发、进度跟踪、异常闭环 | AI现场协调员 |


## 三、技术架构

### 3.1 整体架构（四层设计）

```
┌─────────────────────────────────────────────────────────────┐
│                      交互层（Frontend）                      │
│          Web控制台 ｜ 移动端 ｜ 数字孪生大屏 ｜ 语音交互      │
├─────────────────────────────────────────────────────────────┤
│                   智能体层（Agent Layer）                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐      │
│  │ 调度Agent │ │ 运维Agent │ │ 质量Agent │ │ 知识Agent │      │
│  │ (Python) │ │ (Python) │ │ (Python) │ │ (Python) │      │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘      │
│                    LangGraph / AutoGen 编排                  │
├─────────────────────────────────────────────────────────────┤
│                   服务层（Service Layer）                    │
│    Java微服务（Spring Cloud）:                              │
│    设备数据服务 ｜ 工单服务 ｜ 用户服务 ｜ 通知服务 ｜ 日志    │

├─────────────────────────────────────────────────────────────┤

│   时序数据库(InfluxDB) ｜ 关系库(PostgreSQL) ｜ 向量库(Milvus)│
│   工业协议采集（OPC UA / Modbus / MQTT）      │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 技术栈详解

**Java层（服务底座）** ：
- Spring Boot / Spring Cloud —— 微服务架构
- Spring Security —— 权限与认证
- Kafka / RabbitMQ —— 异步消息与事件驱动
- Redis —— 缓存与分布式锁
- JPA / MyBatis —— 数据持久化
- Docker / K8s —— 容器化部署

**Python层（Agent智能体）** ：
- LangChain / LangGraph —— Agent工作流编排
- FastAPI —— Agent API服务
- Pydantic —— 数据校验
- 大模型接口 —— 通义千问/DeepSeek等
- Milvus —— 向量检索（RAG知识库）
- pybind11 —— Python调用C++底层库（工业协议解析）

**Java ↔ Python 通信**：
- RESTful API（同步调用）
- gRPC（高性能内部调用）
- Kafka（异步事件驱动）

### 3.3 多智能体协作流程示例

以**设备突发故障**场景为例：

```
1. 设备传感器异常 → Kafka事件 → Java服务层接收
2. Java服务触发 → 运维Agent (Python) 启动分析
3. 运维Agent调用：
   - 查询时序数据库（设备历史数据）
   - 查询向量库（历史故障案例）
   - 调用大模型（根因推理）
4. 运维Agent输出 → 故障诊断 + 维修建议
5. 调度Agent (Python) 接收 → 评估影响 → 生成调整方案
6. Java服务层 → 下发工单 → 通知相关人员
7. 执行协同Agent → 跟踪维修进度 → 验证恢复 → 闭环
```


## 四、功能需求

### 4.1 调度智能体（Scheduler Agent）

| 功能模块 | 详细描述 | 优先级 |
|----------|----------|--------|
| **智能排产** | 基于订单优先级、设备状态、物料齐套、人员排班，自动生成最优排产计划 | P0 |
| **急单响应** | 检测到急单插入时，自动评估影响、生成调整方案（换线建议、加班建议） | P0 |
| **产能预警** | 预测未来3天产能缺口，提前预警并建议应对措施 | P1 |
| **换线优化** | 智能推荐“产品-机台”最优组合，最小化换线时间 | P1 |
| **调度模拟** | 支持“what-if”模拟，人工确认后再发布 | P2 |

### 4.2 设备运维智能体（Maintenance Agent）

| 功能模块 | 详细描述 | 优先级 |
|----------|----------|--------|
| **实时健康监测** | 接入设备PLC/SCADA数据，实时计算设备健康评分 | P0 |
| **预测性维护** | 基于PHM算法，预测关键部件剩余寿命，提前14天预警 | P0 |
| **故障诊断** | 异常发生时自动诊断根因，匹配历史案例推荐解决方案 | P0 |
| **维保计划生成** | 自动生成维保工单，联动排产计划选择最优停机窗口 | P1 |
| **备件管理** | 基于预测结果自动生成备件补货建议 | P1 |
| **健康度报告** | 事后输出分层健康度报告（设备级/产线级/车间级） | P2 |

### 4.3 质量分析智能体（Quality Agent）

| 功能模块 | 详细描述 | 优先级 |
|----------|----------|--------|
| **不良实时监控** | AOI/SPI检测数据实时接入，异常自动告警 | P0 |
| **根因分析** | 基于知识图谱+深度学习，定位质量隐患原因（人/机/料/法/环） | P0 |
| **工艺参数优化** | 分析良率与参数关联，推荐最优工艺参数组合 | P1 |
| **缺陷预测** | 基于历史数据预测批次缺陷率，提前干预 | P1 |
| **质量追溯** | 一键追溯不良品的物料批次、设备参数、操作人员 | P1 |

### 4.4 知识助手智能体（Knowledge Agent）

| 功能模块 | 详细描述 | 优先级 |
|----------|----------|--------|
| **文档智能检索** | 自然语言查询SOP、设备手册、工艺文件，响应时间<3秒 | P0 |
| **操作指引** | 基于当前工单/设备状态，主动推送操作提示 | P1 |
| **经验问答** | 基于RAG架构，回答“如何解决贴片偏移”等问题 | P0 |
| **培训辅助** | 新人可随时提问，降低培训成本 | P2 |

### 4.5 执行协同智能体（Execution Agent）

| 功能模块 | 详细描述 | 优先级 |
|----------|----------|--------|
| **指令下发** | 将AI决策结果转化为可执行指令（工单、维修单、参数调整） | P0 |
| **进度跟踪** | 实时跟踪工单执行进度，异常自动上报 | P0 |
| **异常闭环** | 异常从发现→分析→处置→验证→关闭，全流程闭环管理 | P0 |
| **人机协同** | 复杂决策需人工确认，简单决策自动执行 | P1 |

### 4.6 系统管理功能（Java服务层）

| 功能模块 | 详细描述 | 优先级 |
|----------|----------|--------|
| **设备管理** | 设备台账、协议配置、数据采集管理 | P0 |
| **用户权限** | 基于角色的访问控制（RBAC） | P0 |
| **工单管理** | 生产工单/维修工单的全生命周期管理 | P0 |
